# VideoCleaning — план разработки

Лёгкий видеоредактор на Rust для удаления элементов (в основном текста)
с 2D-анимации.

## 1. Цели и ограничения

### Цели
- Загрузка видео, покадровый просмотр, навигация.
- Выделение элементов для удаления тремя способами:
  1. **Прямоугольник** — на кадре, с привязкой к диапазону времени.
  2. **Кисть / полигон** — произвольная маска.
  3. **Автоопределение текста** — детекция на кадре + ручная правка.
- Скрытие (инпейнтинг) элементов, Основной режим — нейросетевой,
  упрощённая модель; классические алгоритмы — как быстрый запасной.
- Экспорт результата в видеофайл с сохранением аудио.

### Ограничения / принятые решения
- **Чистый Rust** по максимуму: без Python, без привязок FFmpeg через C.
- Декодирование H.264 на 100 % чистом Rust пока не существует; используется
  **системный FFmpeg как внешний процесс** (только CLI, без линковки).
  Архитектура — трейт `CodecBackend`, чтобы позже подменить на чисто-растовый
  декодер без переписывания остального кода.
- Целевая платформа: **Linux** (с моментов на Windows/macOS — не блокирует).
- Модель нейросети — маленькая (работает в реальном времени на CPU/GPU),
  веса поставляются в комплекте (ONNX/burn-модель), обучение происходит
  отдельно и не входит в обязанности пользователя.

| Область            | Крейт / инструмент            | Примечание                          |

### Поток данных

```
файл → ffprobe → метаданные (fps, разрешение, аудио)
     → ffmpeg (rawvideo pipe) → кадры RGBA
     → [детект текста (опц.)] → маски
     → пользователь правит маски (прямоугольник / кисть / полигон)
     → инпейнтинг pipeline (bg → nn → telea)
     → кадры обратно → ffmpeg (pipe → H.264) + аудио (copy)
```

### Стратегия скрытия (pipeline)

1. **Фон**: если маска статична и фон под ней меняется редко
   (обычно true для 2D-анимации), берём пиксели из ближайшего кадра,
   где фон «чист» (или медиана соседних кадров за интервал до текста).
2. **Нейросеть**: если фон динамичный — инпейнтинг маленькой CNN
   (упрощённый аналог LaMa: encoder-декодер + FFC-блоки).
3. **Классика**: Telea / Navier-Stokes — быстрый fallback и для мелких
   масок, где разница незаметна.

## 4. Фазы разработки (этапы)

### M0 — Каркас (0.5–1 неделя) — ✅ ВЫПОЛНЕНО
- Рабочий workspace, крейты-скелеты, README/.gitignore.
- `vc-codec`: открытие файла через `ffprobe`, декодирование первого кадра
  в RGBA-буфер (`ffmpeg -i in -f rawvideo -pix_fmt rgba -`).
- `vc-gui`: окно ~ мини-viewport, появляется кадр как `egui::Image`.
- **Критерий**: открывает MKV/MP4, показывает кадр, ресайзится.

### M1 — Навигация и таймлайн (1 неделя) — ✅ ВЫПОЛНЕНО
- Плавная навигация по кадрам (кэш LRU ~30 кадров, prefetch ±1 с).
- Таймлайн: ползунок, маркеры, fps/таймкод.
- **Критерий**: не теряется отклик UI при скраббинге 1080p.

### M2 — Маски (1 неделя) — ✅ ВЫПОЛНЕНО
- `vc-core::mask`: битмапка маски + type (Rect, Brush, Polygon), зона
  действия по времени (start/end кадры).
- Viewport: рисование прямоугольника мышью, кисть с радиусом,
  undo/redo (stack масок).

### M3 — Классический инпейнтинг (1–1.5 недели) — ✅ ВЫПОЛНЕНО
> Реализован Telea (FMM + взвешенное среднее). Navier-Stokes отложен:
> 54 мс/кадр 1080p уже с запасом закрывает критерий скорости;
> NS станет опциональным улучшением при необходимости.
> Бенчмарк: `cargo run -p vc-inpaint --release --bin telea_bench`.
- `vc-inpaint::telea` и `ns` на чистом Rust (порт алгоритма, ~400 строк).
- Параллельная обработка по строкам (`rayon`).
- Применение к выделенному диапазону кадров, live-превью на текущем кадре.
- **Критерий**: удаление статичного текста-субтитра на 1080p за <1 с/кадр.

### M4 — Восстановление фона (1 неделя) — ✅ ВЫПОЛНЕНО
> Заполнение дыры кадрами-донорами (−1, +1, −2, +2 …; до 90 в сторону) через
> lookup-замыкание (ленивые клоны). Остаток закрывает Telea автоматически.
> Backward-prefill в Player подтягивает до 240 кадров перед началом маски
> через команду `PrefillBackward`; превью перечитывается по ревизии кэша.
- Анализ соседних кадров (медиана / поиск «первого чистого» кадра).
- Автовыбор стратегии: bg → telea (если bg невозможен).

### M5 — Нейросетевой инпейнтинг (2–3 недели) — ✅ ВЫПОЛНЕНО (упрощённо)
> burn 0.22 + Flex (чистый Rust CPU, SIMD) — без ONNX/чекпоинтов.
> `nn.rs`: малый U-Net (2×stride-энкодер → ботлнек → декодер со skip) обучается
> **на месте** (self-supervised): случайный dropout ~25% известных пикселей кропа,
> входная маска = реальная дыра | dropout, супервизия только замаскированных
> пикселей известной области. Cosine-распад lr, бюджет шагов адаптивен к площади
> кропа (50–3000). Дыра > max_side=128 → откат на Telea. Тензоры — channel-major,
> [R;G;B] по плоскостям. Ограничения: рецептивное поле ~15 px, углы дыры могут
> «плыть» на ±16 ступеней; pretrained-модель (LaMa/ONNX) — следующая итерация.
- Обучить/взять упрощённый LaMa-tiny, экспортировать в ONNX.
- `burn` с backend Libm/CPU + импорт ONNX (`burn-import`).
- Инференс на CPU, опционально GPU (`burn` с wgpu).
- **Критерий**: инпейнтинг 128×128 патча < 0.5 с; визуально лучше Telea.

### M6 — Автоопределение текста (1.5 недели) ✅
- ~~SWT~~ детектор упрощён и заменён более робастным: локальный контраст
  (box-mean через интегральное изображение) → бинаризация обеих полярностей →
  8-связные компоненты «чернил» → эвристики (размер, габариты, заполнение ≥16%
  — кольца/рамки отсекаются) → группировка штрихов в строки (union-find,
  горизонтально и вертикально, для японского текста).
- Группировка в слова/строки → предложенные прямоугольники-маски.
- GUI: кнопка «🔍 Найти текст на кадре» в левой панели — детекция на текущем
  кадре (~15 мс при 1920×1080), результат — пачка прямоугольных масок
  от текущего кадра до конца (один undo), далее пользователь правит/удаляет.
- Трассировка `VC_TRACE=1` печатает число штрихов/групп и причины отбраковки.
- Тесты `vc-detect`: штрихи на светлом фоне, светлый на тёмном, плоский кадр,
  два слова строкой, мягкий крупный объект (круг) не «текст».
- Попутно исправлено: undo/redo теперь инвалидируют превью (`doc_rev`).
- Ограничения v1: глобально выбирается доминирующая полярность текста на кадре
  (тёмный-на-светлом или светлый-на-тёмном); очень мелкий текст (<8 px) и
  сложная насущная типографика могут не детектироваться — ручные маски остаются
  основным инструментом, детекция — подсказка.

### M7 — Экспорт и полировка (1 неделя) ✅
- Кодирование через pipe: `ffmpeg -f rawvideo -pix_fmt rgba -i - -i SRC
  -map 0:v -map 1:a? -c:v libx264 -crf CRF -pix_fmt yuv420p -c:a copy OUT`.
- Соседние кадры-доноры: скользящее окно (span по лимиту байт, до
  MAX_NEIGHBOR_SPAN), рамка за окном — Telea дотягивает (как в превью).
- GUI: диалог экспорта (путь, CRF 14–28, стратегия = превью), прогресс-бар
  в верхней панели, кнопка «✋ Стоп» (отмена — рабочий поток останавливается
  на ближайшем кадре, файл с уже записанными кадрами остаётся).
- Проект: `.vcproj` — JSON (version, source, regions), serde-derive на
  `Shape`/`MaskRegion` в vc-core; сохранение/загрузка через rfd-диалоги,
  при загрузке видео из проекта открывается автоматически.
- Пути назначения по умолчанию: `имя_clean.mp4`.
- Интеграционные тесты: экспорт lavfi-видео с маской (проверка h264+audio
  в выходе через ffprobe) и отмена по флагу.
- README.md: возможности, сборка, архитектура.
- Release-сборка: `cargo build --release` — бинарь ~24 МБ (thin LTO).
- Замеченное в тестах: ffmpeg умирает без путевого назначения — теперь stderr
  энкодера попадает в сообщение об ошибке (полезно для диагности кодеков).

### Поправка M5 (после пользовательской проверки)
- Стратегия Neural при дыре > 128 px теперь откатывается не на чистый Telea,
  а на **фон-доноры + Telea-остаток** (как стратегия Background) — движущиеся
  титры закрываются донорами почти идеально, смаз уходил раньше.
  Предикат `nn::hole_fits` (тест `hole_fits_matches_rejection`).
- Подпись превью честная: «нейросеть: дыра > 128 px → фон [...] + Telea (…px)».

### M5c.1 — «Выравнивание доноров по движению» — фиксы после проверки
- SAD-маска blend-нить: чтение донора с clamp к краю (OOB-штраф маскировал
  точную фазу); стартовый шаг блок-матчинга сужен до 4 px (узкие фазовые
  оптимумы попадают в coarse-сетку); тай-брейк «ближе к нулю».
- `retouch_frame` (background.rs, M5c.1): покадровая ретушь по
  доказательствам —
  1. глобальный сдвиг каждого соседа (блок-матчинг по вне-маске сэмплам);
  2. кандидаты фона пикселя с ВСЕХ выровненных соседей;
  3. ≥3 кандидатов → робастная медиана; замена ТОЛЬКО если текущий пиксель
     отличается сильнее порога (26/255 по max каналов); целые пиксели не
     трогаются никогда («фотошоп»);
  4. мало кандидатов (1–2) + похоже на текст (ink) → NN-дыра; мало кандидатов
     на целом фоне → пиксель не трогаем;
  5. статичный текст: `static_to_hole` (Neural) → NN-дыра на перерисовку.
- `ink_mask` (локальный контраст box-mean через интеграл): текущий кадр —
  «похоже на текст прямо сейчас» (без дилатации), NN-дыра дальше уточняется
  пересечением с дилатированной ink.
- `Mask::intersected` (vc-core).
- `patchmatch.rs`: **content-aware fill** (Barnes 2009, упрощённый) —
  NNF-поиск патчей (пропагация + ужимающийся случайный поиск по валидным
  центрам), голосование перекрывающимися патчами с весом 1/(cost+1).
  Резкие фазово-точные результаты на плоских/текстурных фонах; seed
  детерминирован. Тесты: `flat_filled_exactly`, `texture_continues_at_edges`.
- Pipeline Neural: `ретушь → (спорные штрихи) PatchMatch → (нет соседей)
  self-supervised NN → фон+Telea`. Background: `ретушь → Telea на остаток →
  старый донор-филл`.
- Тест `neural_keeps_background_bytes`: заменены только текстовые пиксели,
  фон байт-в-байт. Весь воркспейс: 39 тестов, 0 падений.
### M5c — нейро-ПЕРЕРИСОВКА (первая итерация, вытеснена M5c.1)
> Историческая запись: первая версия repaint с донорской супервизией (U-Net
> учится на выровненных донорах). Сохранилась в `nn.rs::neural_repaint`
> (используется, если нет соседей и дыра влезает), в пайплайне Neural её роль
> перешла к ретуши + PatchMatch (M5c.1).
- `nn.rs::neural_repaint(frame, hole, regions, frame_index, cfg, lookup)`:
  - **Донорская супервизия**: на каждом шаге обучения случайный сосед ±1..±8;
    где у донора маска пуста — его пиксель = честная цель (MSE), где у донора
    тоже текст — супервизии нет. Плюс scatter-dropout известной области
    (самосогласованность, вес 0.3). Cosine-распад lr сохранён.
  - **Сеть глубже**: 3 уровня энкодера (→/8), рецептивное поле ≈40 px (было
    ~15), новая архитектура d-ветки со skip-конкатенациями на двух уровнях.
  - **Скользящее-окно инференс** с feather-смешением (stride = side/2,
    вес = ramp от края) — дыры ЛЮБОГО размера, одно обучение на кадр.
- Пайплайн Neural: repaint → (нет доноров: self-supervised одиночный кроп)
  → (не влезает: фон-доноры + Telea). Отката «голый Telea» первым делом больше
  нет.
- Подписи GUI обновлены: «нейросеть: перерисовка (обучение на соседних
  кадрах, медленно)».
- Тесты: `repaint_supervised_by_donors` (шахматка под текстом восстанавливается
  из донора, не блюрится), `repaint_tiled_big_hole` (дыра 80px при кропе 32 —
  тилинг закрывает её фоном).
- Стоимость: ~600 шагов-обучение на кадр (по умолчанию): превью ~4-6 с/кадр
  CPU, экспорт с Neural — пропорционально дольше (каждый кадр учится заново:
  это осознанное «перерисовывание покадрово», а не наложение фильтра).

### M5b — предобученная LaMa через ONNX Runtime (решение: вариант B)
Референс: https://github.com/YaoFANGUK/video-subtitle-remover (VSR).
Их собственные выводы: для **аниме** лучший из их алгоритмов — LaMa (STTN —
для живого видео, ProPainter — жёсткие движения). Мы повторяем цепочку
«ретушь-по-доказательствам (наша M5c.1) → LaMa → PatchMatch → Telea», где
ретушь заменяет их OCR-детекцию + جمع по кадрам.

- Модель: `ogkalu/lama-manga-onnx-dynamic` (AnimeMangaInpainting,
  FourierUnitJIT, динамические формы, ~197 МБ) → `models/lama-manga-dynamic.onnx`.
  Файл ищется: env `VC_LAMA_PATH` → `models/…` → рядом с exe.
- **Решение пользователя (вариант B): рантайм — ONNX Runtime** (динамическая
  библиотека Apache-2.0 в комплекте: `lib/libonnxruntime.so.1.20.1`),
  Rust-обёртка `ort = 2.0.0-rc.15` (feature `load-dynamic`). tract-onnx
  отвергнут по фактам: manga-модель — 27+ мин/окно без into_optimized;
  статические экспорты (big-lama, lama-fp32) в tract не типизируются вовсе
  (aten_rsub / баг Range). ORT снимает обе проблемы.
- Тайминги ORT 1.20.1 (CPU, 12 ядер): окно 304² — **0.42–0.47 с**,
  окно 512² — **1.5 с** (первый прогон включает аллокации).
- **GPU-инференс (сделано)**: ORT-GPU 1.20.1 (`lib/libonnxruntime_providers_cuda.so`,
  694 МБ из официального релиза) + CUDA-12/cuDNN-9 рантайм от NVIDIA
  (wheel-пакеты: cudart/cublas/cufft/nvrtc/nvjitlink/cudnn → `lib/`, sonames
  12/9 подтянуты rpath `$ORIGIN`). CUDA EP включён в `ort` (feature `cuda`)
  и в `lama.rs`: VC_GPU≠0 (по умолчанию включено) → `Environment::with_execution_
  providers([CUDA])`, неудача — автоповтор на CPU. Тайминги RTX 4070 SUPER:
  304² — **76 мс** повторный, 512² — **52 мс** повторный (первый прогон ~0.3–0.4 с
  — хип-аллокации); CPU-фолбэк через VC_GPU=0.
- **Диагноз и фикс «каши» на кадре титров** (полупрозрачный текст на небе/воде,
  t=3 c «原作 入江亜季», фазовые дампы `bin/lama_debug` → BMP A/B/C/D/E/F):
  1) маска LaMa «nn_hole ∩ ink(контраст 48)» давала 0–203 px: медиана доноров
  ≈ текущий пиксель (текст одинаково виден во всех кадрах) → не спорный; а
  полупрозрачные штрихи на светлом фоне не проходят ink-порог → LaMa не
  вызывалась либо красила 3 точки; 2) где ретушь «заменила» пиксель медианой
  доноров на движущейся воде — получилась каша (выравнивание мимо).
  **Фикс**: маска LaMa = **весь регион пользователя** (он сам указал «удали
  тут»), ретушь остаётся спереди как предобработка; LaMa перерисовывает дыру
  из окружения целиком → текст удалён полностью и чисто (дампы E/F);
  `filled_by=Lama`. Без модели — прежняя узкая маска (старые юнит-тесты).
- **Качество/«полоса» после удаления**: сравнение моделей на кадре титров —
  manga-dynamic лучше всего; lama-fp32 (порт big-lama, Places) — сильнее
  «размывает»; big-lama.onnx сам по себе грузится отказом (не используется).
  Увеличение контекста окна MAX_SIDE 512→640 (динамическая manga-модель
  поддерживает кратность 8) сделало полосу слабее, но при больших дырах
  LaMa фундаментально рисует плоское заполнение: заметна светлая полупрозрачная
  полоса по границам ректа + слабая сетка окон. Попытки: узкие штриховые
  дыры (rect минус replaced) — хуже (мураш доноров + остатки текста);
  «демиксинг» полупрозрачного текста регрессией по времени (α-модель,
  python-прототип) — прокси из боковых полос не репрезентативен, браковано.
  **Вывод**: для «вовсе незаметного» результата по живому фону — видео-
  инпейнтинг (STTN/ProPainter/E2FGVI из M8): temporal-модель восстановит
  фон из соседних кадров. Зафиксировано как следующая крупная цель.
- **UI**: современная тёмная тема (apply_style: панели/виджеты/акцент),
  левая панель — инструментные иконки с tooltip'ами, свёртываемые разделы
  (стратегия, свойства, подсказки), статус-точка модели; правая панель —
  карточки масок с цветовым маркером и компактным рядом настроек диапазона;
  полировка таймлайна.
- **Таймлайн (переработан)**: скраб перетаскиванием по дорожке (не только
  клик), колесо мыши ±1 кадр (Shift — ±25), подсказка «таймкод · кадр» под
  курсором, адаптивные секундные метки (шаг 1/2/4/8…с), кнопки ‹‹ / ‹ / › /
  ›› вокруг слайдера (±25 / ±1 кадра) и прыжки по границам диапазонов масок
  (`jump_mask_boundary`: ближайшие start/end+1 всех регионов в обе стороны).
- **Анти-мигание превью**: поле `last_frame` в VcApp хранит последний
  показанный кадр; при пустом кэше (скраб/перемотка/декодер не успел) вьюпорт
  рисует его вместо заглушки «⏳ декодирование…» (заглушка остаётся только до
  первого кадра), плюс throttled `seek` + repaint 30мс пока кэш пуст.
  `last_frame` сбрасывается в `open_video`.
- **Чин Playback-застои**: (1) тики playback не убегают от декодера: если
  next-кадра нет в кэше — тик пропущен, re-seek только после 300мс застоя;
  (2) повторные seek'и из вьюпорта убраны (каждый Seek убивает поток
  декодера); (3) `goto()` обновляет focus кэша (вытеснение держит окно
  вокруг просмотра); (4) корень: кэш насыщался окном [0..63], декодер в ~12×
  realtime убегал далеко вперёд и его вставки вытесняли сами себя — кадры
  будущего не попадали в кэш, playback спотыкался каждые ~36 кадров
  (63/102/142/181, подтверждено пробником `bin/playback_probe`). Фикс:
  read-ahead лимит `READ_AHEAD=8` в player.rs (декодер паркуется мягко,
  reader открыт, seek'и обрабатываются). Пробник: застоёв 42 → 1 (129мс на
  старте); превью вид во время playback не считается (декодирует декодер);
  test vc-codec 4/4.
- Модели: manga-dynamic — основная (~0.5 с/окно, вход и выход [0..1],
  адаптивная сторона окна); `models/lama-fp32.onnx` — fallback
  (1.5 с на 512², статические формы, выход в [0..255]).
- Авто-норма выхода: недырные пиксели модель воспроизводит ×1 или ×255 —
  детектируется по недырным пикселям окна, выход делится на коэффициент
  (обе модели дают угол_err=0 после выравнивания).
- `lama.rs`: адаптивная сторона окна (=bh+192, кратность 8, кламп 64..512),
  sliding windows по bbox (перекрытие 50%), feather-голосование, запись
  ТОЛЬКО пикселей дыры; сессия ORT под Mutex (run требует &mut), ленивая
  инициализация через `ort::init_from` (dylib) → `Session::builder(&env)`.
- Пайплайн стратегии Neural: ретушь → (спорные штрихи) LaMa → PatchMatch →
  Telea. Переключатель `NeuralConfig::use_lama` (в юнит-тестах false —
  модель не дёргается).
- Прозрачность: `InpaintResult::filled_by ∈ {Lama, PatchMatch, Telea}`,
  GUI: «умное удаление: ретушь по кадрам [±k] + LaMa (предобученная модель)».
- Probe: `cargo run -p vc-inpaint --release --bin lama_probe` — синтетика,
  env `VC_PROBE_SIDE` (сторона окна), проверяет сохранение фона и тайминг.
- Перенесено из VSR: принцип «модель живёт рядом, результат — безразруш.,
  запись только в маске»; полоса `W*3/16` и OCR-детекция PP-OCR нам не нужны —
  ретушь уже отделяет честные пиксели от текстовых в разы быстрее и без модели.

### M8 — Видео-инпейнтинг: ProPainter сайдкар (выбран вместо порта STTN)
- **Цель**: «вовсе незаметное» удаление в живом фоне — только видео-модель.
- **Память**: ProPainter на 1080p в 12 ГБ не влезает (720p fp16 ≈ 7–8 ГБ);
  решение — кроп вокруг bbox всех масок (+контекст 48px, кратность 8) с
  возвратом в полноразмерный кадр; диапазон кадров = активные рамки ±20 запаса.
- **Сайдкар** `tools/propainter/inpaint_cli.py`: несколько **сегментов** —
  кластеры масок по времени (Rust готовит план `plan_video_export` →
  `--segment START:COUNT:X:Y:W:H`, повторяемый). Для каждого сегмента —
  свой кроп (bbox только его масок + контекст 48px, кратность 8) и свой
  прогон ProPainter; соседние диапазоны (зазор ≤ 2×запаса 20 кадров)
  сливаются. Один проход вставки по всему ролику: кадры сегментов
  собирают результат, между сегментами копируются без изменений — на
  выходе полная длина (звук добавляет Rust-муксер). Маски: raw u8
  (`vc_core::rasterize`, `<gf:09d>.raw` глобально), нарезка кропом → PNG
  0/255. Прогресс: `PROGRESS extract <f01>` (0..1 глобально),
  `painter_run k n` (завершён сегмент k из n), `paste <f01>`, `done`.
- **Rust** `crates/vc-gui/src/export_ai.rs`: план (bbox фигур, кроп кратный
  8), запись масок (dilated(2)), спавн `tools/venv/bin/python`, парс
  stdout (PROGRESS/ERROR), stderr → `<out>.vcvideo.log`, муксер звука
  (`-map 1:a? copy`), чистка work-каталога. GUI: чекбокс «Видео-инпейнтинг
  ProPainter» в окне Экспорта (тускнеет без `tools/venv`); фазы через
  `ExportMsg::Phase` (нативный экспорт фазы не шлёт).
- **Чинушка**: torchvision ≥0.25 удалил `.io.read_video` — в патче
  `inference_propainter.py` cv2-фолбэк (BGR→RGB, fps из CAP_PROP_FPS).
- **Фикс «статичный кадр после диапазона»**: video-only файл покрывает
  ВЕСЬ ролик — вне диапазона кадры копируются без изменений (иначе видео
  короче аудио и плеер замораживает последний кадр). Проверено: обработка
  20 кадров → на выходе все 1514.
- **Прогресс**: stdout-фазы дают рубежи 0—6—90—100%; гранулярность
  GPU-фазы даёт поллер tqdm в Rust (`spawn_tqdm_poller`): вычитывает
  проценты из `<out>.vcvideo.log` и файл состояния `painter_state`
  ("k n" — сегмент k из n, пишет python), строит глобальный процент
  (k + pct/100)/n → полоса 6—90%.
- **fp16**: сайдкар всегда передаёт `--fp16` (вдвое меньше VRAM и
  быстрее; на CPU inference его игнорирует).
- Установка: `tools/venv` (python3.12, torch 2.14.1+cu126), зависимости
  repo, веса в `tools/propainter-repo/weights/` (~200 МБ).
- Порт STTN (VSR) остаётся запасным вариантом.





## 5. Риски и их снижение

**OOM-инциденты (01:06/01:14, vscode снесён systemd-oomd)**: swap — это zram
(в ОЗУ!). Всё, что запущено из терминала VSCode, живёт в его cgroup, и при
пике (RAM+zram > 90%) oomd убивает самый толстый cgroup целиком — VSCode.
Снижение: `scripts/run-gui.sh` запускает приложение в отдельном scope
`videocleaning.scope` c `MemoryHigh=6G MemoryMax=10G` — в худшем случае
умирает сам редактор; python-сайдкары наследуют scope GUI. Тяжёлые тесты
(vcam, cargo, pip) из сессии — запускать по одному, не параллельно.

| Риск                                        | Снижение                                        |
|---------------------------------------------|--------------------------------------------------|
| Декод/энкод видео «не чисто Rust»           | трейт `CodecBackend` — swap-ABLE, FFmpeg только как процесс  |
| Инференс медленный на старом железе         | маленькая модель + тайлинг + rayon + GPU-опция    |
| SWT даёт ложные срабатывания                | ручное подтверждение, режим «подсказки»           |
| Память на длинных видео                     | LRU-кэш кадров, on-disk буфер для батчей        |
| Инпейнтинг «дёргается» между кадрами        | temporal consistency: маска применяется соглас. |

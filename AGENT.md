# AGENT.md — как работать с этой кодовой базой

Инструкция для ИИ-агентов (и новых контрибьюторов) по структуре, командам
и подводным камням проекта.

## Что это

`VideoCleaning` — лёгкий видеоредактор на Rust для удаления текста/логотипов
с 2D-анимации. GUI на eframe/egui, декод/кодирование через системный ffmpeg
(отдельный процесс, никакого C-байндинга). Опциональный AI-экспорт через
python-сайдкар с [ProPainter].

## Команды

```sh
cargo build --release -p vc-gui   # сборка GUI (target/release/videocleaning)
cargo build --release             # весь workspace
cargo test --workspace            # тесты (тест экспорта зовёт реальный ffmpeg)
./scripts/run-gui.sh              # запуск GUI в systemd scope с лимитами памяти
cargo clippy --workspace          # линки перед коммитом: держим чисто
```

- GUI перезапускать **только** через `./scripts/run-gui.sh` — он изолирует
  память в `app.slice/videocleaning.scope` (MemoryHigh=6G/MemoryMax=10G),
  чтобы systemd-oomd не убил IDE/терминал, и делает `reset-failed`.
- Отделить отладку сайдкара: `VC_PROPAINTER_KEEP_WORK=1` — рабочие
  директории `/tmp/vc_paint_*` не удаляются.
- Трассировка: `VC_TRACE=1` для плеера/детектора.

## Workspace

| Крейт       | Роль |
|-------------|------|
| `vc-core`   | `Frame` (RGBA8), `Mask`/`Shape` (Rect/Polygon/Brush), растеризация, таймкод. Базовые типы без зависимостей от кодека/UI. |
| `vc-codec`  | ffmpeg/ffprobe-обёртки (`CodecBackend`), метаданные, `Player` (стример + LRU-кэш), нативный `export` (x264 + аудио-мукс). |
| `vc-inpaint`| Стратегии превью: `background` (доноры кадров), `nn` (мини-U-Net), `lama` (ONNX), `telea` (FMM), `patchmatch`; `pipeline` выбирает стратегию. |
| `vc-detect` | Автопоиск текста: локальный контраст → компоненты → группировка в строки (SWT). |
| `vc-gui`    | Приложение: `app.rs` (состояние/UI), `viewport.rs`, `timeline.rs`, `tool_panel.rs`, `masks_panel.rs`, `export_ai.rs` (AI-экспорт). |

Кросс-крейтовые зависимости направлены только «вниз»: gui → {core, codec,
inpaint, detect}; codec/inpaint/detect → core. Расширять поверх этой
иерархии, не заводить циклов.

## AI-экспорт (M8) — ключевой механизм

Строчный поток: `vc-gui/src/export_ai.rs` + `tools/propainter/inpaint_cli.py`.

1. **План** (`plan_video_export`): маски (`MaskRegion`, кадр-диапазоны)
   группируются в кластеры по времени (зазор ≤ 2×запаса = 40 кадров —
   сливаются). Каждый кластер → `ExportSegment { crop, frame_start,
   frame_count }`; кроп = bbox *только своих* масок + 48px контекст,
   кратность 8. Между сегментами кадры копируются как есть — **не
   обрабатываем лишнего**: два клипа по краям ролика = два маленьких
   сегмента, а не 1000+ кадров сквозной обработки.
2. **Растеризация масок**: `vc_core::rasterize(regions, frame, w, h)`
   → `<frame:09d>.raw` (u8 0/255, полный кадр 1920×1080) в рабочий
   каталог `.vc_ai_work/`.
3. **Сайдкар** (`inpaint_cli.py --segment START:COUNT:X:Y:W:H ...`):
   - нарезает кроп-видео и кроп-маски по каждому сегменту;
   - если кроп «тучный» (long side > 1024) — считается в пониженном
     разрешении (INTER_AREA / NEAREST), результат растягивается назад
     при вставке (защита от CUDA OOM: VRAM растёт ~ W×H);
   - прогоняет `inference_propainter.py` по каждому сегменту (`--fp16`
     всегда на GPU, subvideo_length 80);
   - один проход вставки по **всему** ролику: кадры сегментов получают
     результат, остальные — без изменений; на выходе полная длина и звук
     добавляет муксер Rust.
4. **Прогресс** (stdout для парсинга Rust, формат — части: менять только оба
   конца одновременно):
   ```
   PROGRESS extract <f01>       # глобальная доля 0..1, фаза подготовки
   PROGRESS painter_run <k> <n> # завершён GPU-сегмент k из n
   PROGRESS paste <f01>         # доля финального кодирования
   PROGRESS done 1.0
   ERROR <текст>                # перед не-0 exit
   ```
5. **tqdm-поллер** (`spawn_tqdm_poller`): ProPainter пишет проценты в
   stderr (→ `<out>.vcvideo.log`) и файл состояния `painter_state`
   (`"k n"`); поллер раз в 0.5 с строит глобальный процент
   `(k + pct/100)/n` → полоса 6–90%.
6. **Логи** для пользователя/отладки: `<out>.export.log` (фазы, проценты,
   тайм-метки, итог) и `<out>.vcvideo.log` (stderr ProPainter).

Границы экспорта: GUI-сообщения `ExportMsg::{Progress, Frames, Phase,
Done, Failed}` идут по одному каналу; `Progress(done, total)` — по полосе
(0..1000), `Frames` — счётчик кадров этапа (кадры + ETA в UI).

## Подводные камни

- **VRAM**: ProPainter на GPU ест ~W×H памяти активаций. Кропы держи
  маленькими (смысл всего сегментно-кропового дизайна), fp16 обязателен,
  wide-кропы > 1024 по длинной стороне — занижать разрешение.
- **RAM/systemd-oomd**: тяжёлое запускать изоляцией (`run-gui.sh`).
  Прямой запуск из VSCode-терминала опасен для сессии пользователя.
- **ffmpeg** ищется через `FFMPEG_PATH`/`FFPROBE_PATH`, затем PATH;
  сбилженный imageio-ffmpeg живёт в сайдкаре.
- **Тонкости ffmpeg**: эпохи нет — тайминги по кадрам; счётчик кадров
  итогового видео обязан равняться `frame_count` исходника (paste-фикс
  сайдкара: full-length walk по исходнику, иначе плееры крутят статику).
- **Python**: всё сайдкарное — только `tools/venv/bin/python`; синтаксис
  проверять `python -m py_compile` (тестов python-части нет).
- **Нумерация файлов**: маски — глобальные номера кадра с pad 9
  (`000000042.raw`); кроп-маски ProPainter — локальные с pad 6
  (`000042.png`) — не перепутать.
- `Cargo.toml` edition 2024 → нужен Rust 1.85+.
- Репозиторий не тянет тяжёлое: `tools/venv`, `tools/propainter-repo`,
  `weights/`, `models/`, `lib/`, `target/` — всё в `.gitignore` (инструкции
  по установке в README).

## Стиль

- Русский язык в комментариях и пользовательских строках — это
  сознательный выбор проекта; писать так же.
- Имена/модули/english identifiers — стандартно.
- Комментарии объясняют «почему», а не «что».
- Новые фазы/протоколы экспорта: сразу обновлять export-логи и
  `PLAN.md` (там журнал решений по этапам M0–M8).

## Прежде чем коммитить

```sh
cargo test --workspace && cargo clippy --workspace -- -D warnings
```

Проверено: сборка и тесты не требуют GPU; AI-режим проверяется вручную
на реальном видео (см. README, раздел «AI-режим»).
